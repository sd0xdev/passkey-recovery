# Release plan

How a version of Passkey Recovery becomes public. Every step below that publishes something is a **maintainer action**; nothing in this repository's scripts publishes, tags, uploads or deploys on its own.

**Current state:** the source repository is public and its CI runs (steps 1–2 below). The website is deployed ([deploy-plan.md](deploy-plan.md)), ahead of any Release. No tag, GitHub Release or tarball exists (steps 3–4 have not run).

## What a release contains

| Artifact | Built by | Where it goes |
|----------|----------|---------------|
| Public source tree | `npm run release:export -- <dir>` (exact allowlist `scripts/release/public-allowlist.json`, `MANIFEST.sha256` + digest; `.npmrc` is generated by the export with only `engine-strict` and `save-exact`, never copied from the working copy) | The public repository `sd0xdev/passkey-recovery` |
| Runner package `passkey-recovery-<version>.tgz` | `npm pack` after `npm run build` (files listed in `package.json` `files`) | GitHub Release `v<version>` asset, with its sha256 in the release notes |
| Website build `dist-hosted/` | `npm run build:hosted` | Cloudflare Workers Static Assets, see [deploy-plan.md](deploy-plan.md) |

`package.json` keeps `"private": true` so `npm publish` refuses to run. The package is distributed as a release file and started with `npm exec --yes --package ./passkey-recovery-<version>.tgz -- passkey-recovery` (the command `src/config/release.ts` prints and `release:pack-smoke` runs).

## Checks before a release

Run from the exported tree, not the working copy, so the release is proven to build from the public source alone. First prepare a private deny list outside the repo: a plain text file, one term per line (names, emails, addresses and hashes that must never appear in the public tree); the scanner refuses to run when the file is missing.

```bash
node scripts/release/export.mjs ../passkey-recovery-public --force
DENY_FILE="$HOME/private/passkey-recovery-deny.txt"   # your private deny list, kept outside the repo
node scripts/release/scan.mjs ../passkey-recovery-public --deny-file "$DENY_FILE"
cd ../passkey-recovery-public
npm ci
npm run build && npm run build:hosted
npx playwright install chromium   # first time only
npm run test && npm run test:integration && npm run test:e2e
npm run release:licenses
npm run release:pack-smoke        # npm pack + real npm exec in a clean folder with an isolated cache
```

`release:pack-smoke` writes the tarball, its sha256 and file list to `release-out/`. Optional and slow (needs git, Foundry and network): `npm run release:rebuild-contracts` rebuilds the bundled contract bytecode from pinned upstream commits ([SOURCE.md](../../registry/coinbase-smart-wallet-v1.1/SOURCE.md)).

## Publishing (maintainer)

1. Create the public repository from the exported tree (first release) or push the new tree to it. Turn on **Private Vulnerability Reporting** (Settings → Code security) and confirm the button appears before `SECURITY.md` is relied on.
2. Let CI pass on the public repository.
3. Tag `v<version>` and create the GitHub Release. Upload the tarball from `release-out/` and paste its sha256 into the notes.
4. Download the asset from the release page, recompute its sha256 and compare it to `release-out/` (read-back).
5. Deploy the website again if its files changed ([deploy-plan.md](deploy-plan.md)). The status in the README and the install guides changes only after the read-back passes.

## Versioning

Semantic versioning, 0.x while the tool is early. The version comes from `package.json`; the website and the runner print the same version (`src/config/release.ts`, `passkey-recovery --version`). Three checks handle skew between a page and a runner:

| Check | Where | Effect |
|-------|-------|--------|
| Runner protocol (`RUNNER_PROTOCOL`) | Pairing | A runner that speaks another protocol is refused |
| Package version | `src/ui/Tool.tsx` after pairing | A runner whose version differs from the page shows a version-differs notice; pairing still works |
| Signer API (`SIGNER_API`, `src/config/signerApi.ts`) | `src/ui/gas/useGasPayer.ts`, `GasPanel.tsx` | An older or newer signer gets update guidance instead of the native gas-wallet unlock |

Within one protocol, a page that calls a signer endpoint an older runner does not know still gets a 404 and shows `runner-outdated`; the user restarts with the new package. Skew the three checks do not cover is not detected.
